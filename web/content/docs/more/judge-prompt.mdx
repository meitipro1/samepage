## Both orders, on every node

A model that compares two texts can lean towards whichever comes first, and every validator would lean the same way, so consensus alone cannot catch it. Each node therefore asks twice inside one block: once with the opener's account as A, once with the counterparty's as A. Where the two orders give the same status for a term, that is the status. Where they do not, the term is stored as `DIFFER`: a term the model reads one way in one order and another way in the other is a term the two sides should talk about. The uncertainty is settled in the value, before anything is compared.

## How validators agree

Each validator asks in both orders itself and agrees only when its six statuses are exactly the leader's. There is no tolerance: `MATCH` against `ABSENT` is a disagreement like any other. The one-line notes are the leader's, stored as a reading aid on the result page; they are never compared and never signed.

An answer the contract cannot read as six statuses is asked once more, then fails the round. It never becomes a status. A round where validators disagree stores nothing: the page stays on its check step, and anyone may send `check` again until the window closes. After that, `no_show` closes the page `NOT_AGREED` with both deposits back, because nobody was absent.

A refused write still reaches consensus: validators agree the refusal is the right result, and the transaction reads ACCEPTED. The site counts a write as done only when the status is ACCEPTED or FINALIZED **and** the execution returned; otherwise it shows the sentence below, which the transaction carries in its result payload. A refused write keeps nothing it was sent: a join with the wrong deposit leaves the value with the sender.

`[EXPECTED]` refusals are deterministic and identical on every validator. `[LLM_ERROR]` means the judge's answer could not be read as six statuses, even after one retry; validators then disagree on purpose, so the round rotates to a committee that can answer, and nothing defaults to a status.
